# Ручная сборка пакета mt-c из PR

Проверочные и релизные сборки остаются раздельными. Для редкой установки
тестовой версии на реальный роутер используется **Build PR packages**:
сборка запускается **вручную** и компилирует ровно одну выбранную архитектуру
из исходников текущего HEAD указанного PR.

> **Важное условие GitHub:** кнопка Run workflow появится только после того,
> как файл `.github/workflows/build-pr.yml` окажется в ветке репозитория по
> умолчанию. До слияния добавляющего её PR пользоваться новой кнопкой нельзя.

## Запуск через GitHub Actions

1. Откройте [Actions](https://github.com/dan0102dan/mt-c/actions) →
   **Build PR packages** → **Run workflow**.
2. В выпадающем поле ветки оставьте **основную ветку репозитория**
   (пока `claude/magitrickle-c-rewrite-phase-0-t7iwas`).
   **Не выбирайте ветку PR:** PR определяется по отдельному полю.
3. Укажите `pr_number`: номер **открытого** pull request.
4. Выберите `platform`: `entware` (включая Keenetic) или `openwrt`.
5. Впишите `architecture` — имя существующего файла без `.config`
   в `config/<platform>/` **выбранного PR**. Примеры:
   - Keenetic / Entware: `mipsel-3.4_kn` (получится `.ipk`);
   - OpenWrt: `aarch64_cortex-a53`.
6. Для OpenWrt выберите `openwrt_version`: `24.10.4` для `opkg/.ipk`,
   `25.12.5` для `apk/.apk`, `snapshot` только для поддерживаемых
   в матрице snapshot-архитектур. Для Entware это поле игнорируется.
7. `publish_prerelease = false` — простой файл в **Actions → Artifacts**
   (нужна авторизация GitHub, хранение 14 суток);
   `true` — отдельный тестовый prerelease с прямой ссылкой, хешем SHA256
   и командой установки. Нажмите **Run workflow**.

После выполнения workflow обновляет **один комментарий бота в PR**:
точный SHA источника, выбранную архитектуру, результат сборки, ссылку на
Actions и, при выбранной публикации, URL пакета и команду для установки.
Вместо постоянного `pr-latest` используется неизменный уникальный тег
`pr-<number>-<sha12>-<run_id>`: предыдущие тестовые файлы не
перезаписываются.

### То же самое через gh CLI

Замените `PR_NUMBER` номером **открытого** PR и используйте основную ветку
как контекст выполнения workflow:

```bash
PR_NUMBER=123   # пример: укажите номер своего открытого PR
gh workflow run build-pr.yml \
  --repo dan0102dan/mt-c \
  --ref claude/magitrickle-c-rewrite-phase-0-t7iwas \
  -f pr_number="$PR_NUMBER" \
  -f platform=entware \
  -f architecture=mipsel-3.4_kn \
  -f openwrt_version=25.12.5 \
  -f publish_prerelease=true
```

## Какой код попадает в пакет

При запуске определяется HEAD SHA выбранного PR. При checkout этот SHA
проверяется и сборка прекращается при изменении HEAD. SDK и формат пакета
используются из существующего `build.yml` и `config/**`, как и при
релизной сборке. Для выбора архитектуры используется проверенный
`tools/ci/build_matrix.py` из доверенной версии workflow: поэтому
работают и старые PR без данного скрипта. Сборка по PR использует токен
`contents: read`, отдельный этап публикации — `contents: write`.

Пакет загружается в Artifacts **до** опционального теста в эмуляторе.
Поэтому при падении эмулятора пакет можно получить для диагностики, но
такой результат явно помечается непроверенным. Prerelease публикуется
**только если обязательные проверки успешно завершились**, не подменяет
стабильный релиз и не отмечается как Latest. Событие публикации
`pr-*` не запускает производственную матрицу.

**Ограничения:** проверяется только выбранная платформа и архитектура.
Тест в Router Emulator сейчас предусмотрен для OpenWrt 25.12.5 /
`aarch64_cortex-a53`, а не для всех маршрутизаторов и сетевых сценариев.
Перед установкой на рабочий роутер проверьте архитектуру и сохраните конфиг.
