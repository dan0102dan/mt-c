# Восстановление обновлений на Keenetic / Entware

## Что произошло

На затронутом Keenetic системный `/bin/sh -c` не сохраняет позиционные аргументы, тогда как `/opt/bin/sh -c` передаёт их корректно. Старый встроенный установщик запускал именно `/bin/sh` и передавал через `$1`–`$5` пути к `opkg`, пакету, init-скрипту и временному каталогу, а также формат пакета. Поэтому скачивание могло завершиться успешно, но установка не запускалась с нужными аргументами.

Релиз **0.8.5 также содержит этот дефект**. Переустановка именно 0.8.5 не исправляет механизм последующих обновлений. Проблема не означает, что одинаково затронуты все устройства Entware или OpenWrt.

Исправление выбирает `/opt/bin/sh` для Entware и `/bin/sh` для OpenWrt. Проверка доступности и запуск используют один путь. При отсутствии Entware shell обновление запрещается: автоматического отката к несовместимой системной оболочке нет.

## Пользователям старых сборок

Для затронутых установок нужен один переход на **сборку, уже содержащую исправление**, через системный пакетный менеджер, а не кнопку обновления mt-c. Новый релиз не может изменить код установщика, который ещё работает из старого бинарника.

1. Сохраните изменения и экспортируйте конфигурацию из WebUI на компьютер. Не удаляйте mt-c перед обновлением и не меняйте системный `/bin/sh`.
2. Выберите пакет исправленного релиза под свой target. Точный суффикс показывает `asset_suffix` в `GET /api/v1/system/update`; для затронутого устройства это `entware_mipsel-3.4_kn.ipk`. Не выбирайте пакет только по `uname -m` и не теряйте суффикс `_kn`.
3. Скачайте пакет из GitHub Releases и проверьте SHA-256 по опубликованному digest. Убедитесь, что другая операция `opkg`/обновления не выполняется. Затем установите конкретный локальный файл:

   ```sh
   # Замените путь на скачанный пакет ИСПРАВЛЕННОГО релиза.
   /opt/bin/opkg install /tmp/mt-c-fixed.ipk
   ```

   Это обновление поверх существующей установки, не переустановка с удалением конфигурации. Оно может кратковременно прервать работу сервиса. Не применяйте `--force-*`, если `opkg` сообщает ошибку: сначала разберите полный вывод.

4. Проверьте версию пакета и запущенного backend, затем перезагрузите страницу WebUI:

   ```sh
   /opt/bin/opkg status mt-c
   curl -sS http://127.0.0.1:8080/api/v1/system/update
   ```

   Используйте свой порт вместо 8080; при включённой авторизации откройте API через авторизованный браузер. Версия backend должна соответствовать установленной исправленной сборке, включая ревизию. Если пакет обновился, а backend остался старым, выполните `/opt/etc/init.d/S99magitrickle restart` и проверьте снова.

Альтернатива загрузке файла — `opkg update` и `opkg upgrade mt-c`, **только после появления исправленного пакета в подключённом feed**. Старая версия в индексе feed не означает, что именно она установлена: установленную версию показывает `opkg status mt-c`.

Не публикуйте заменённые бинарники под старым тегом/номером пакета. Исправлению нужен отдельный релиз или новая ревизия, чтобы пакетный менеджер и WebUI однозначно распознали обновление.

## Проверка исправления перед выпуском

Host-тесты включают отдельные варианты реального запуска для Entware и OpenWrt, передачу аргументов, закрытые стандартные дескрипторы, завершение родительского демона, удержание блокировки, перезапуск и очистку файлов. Entware-вариант проверяет также отсутствие shell до запуска и его исчезновение между проверкой и `execve`.

Эмуляция путей в CI не заменяет проверку на устройстве: вручную установить исправленный пакет на затронутый Keenetic, затем проверить обновление через WebUI на ещё одну более новую тестовую ревизию. Проверить изменение версии пакета и backend, сохранение конфигурации и отсутствие незавершённой транзакции.
