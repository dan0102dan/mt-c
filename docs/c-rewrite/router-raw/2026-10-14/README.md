[Детализация по действующим правилам](live-rules/summary.md).
При непрерывной нагрузке на 1000 правилах генератор сам расходовал
около 22% одного CPU с Go и 111% с mt-c. Поэтому измеренная пропускная
способность зависит от всей тестовой связки, включая генератор и штатный DNS.
RSS включает общие страницы библиотек; PSS недоступен на этом ядре.


32 публичных домена, настоящий штатный DNS `127.0.0.1:53`, без dnsstub.
Нагрузку генерирует `dnsload` на самом роутере. Правила включены;
приватные `mtb_` ipsets принимают ответы, но оба семейства iptables и
DNS remap отключены. Проверяется обработка DNS и обновление ipset,
а не маршрутизация пакетов. Рабочий сервис и фоновые службы запущены.

Параметры: 100/1000/10000 namespace-правил, UDP/TCP, 10 клиентов,
3×20 с на пакет, порядок пар Go→C, C→Go, Go→C. Дополнительно —
1000 правил, UDP, фиксированные 20 запросов/с, 3×30 с на пакет.
Каждый запуск — новый процесс, probe, 5 с простоя, 3 с прогрева.
Число/тип правил задаются контролируемым конфигом: это не запись
трафика или конфиг действующих пользователей.

CPU% относится только к демону, 100% = один логический CPU.
Генератор и upstream делят с ним процессор; их влияние ограничивает
capacity-RPS. RSS — память процесса с общими страницами библиотек,
не вся потребляемая память и не оценка освобождаемой RAM. PSS недоступен.
Задержки относятся только к успешным ответам и включают TCP connect.
Таймауты входят в ошибки; ошибки не входят в RPS. Выборка мала для
утверждений о долгосрочной стабильности, холодной рекурсии или другом железе.

[Полный протокол и воспроизведение](../../../../tools/bench/router-benchmark.md).
Старые host-результаты сохранены отдельно; их интерпретация как одинакового
активного сопоставления отозвана из-за выключенной группы (D-80).

Дополнительные точки выполнялись с `--memory-guard`: тестовый процесс
`oom_score_adj=1000`, остановка при MemAvailable <16 MiB или SwapFree <64 MiB.
Штатные zram и настройки памяти не менялись; memory cgroups недоступны.
50 000/100 000: три попытки на пакет/размер остановлены при загрузке;
дополнительно сохранена первоначальная остановка Go на 50 000.
Нет ни RPS, ни RSS после нагрузки для этих попыток. Графики показывают
отдельные отметки предохранителя без числовой метрики и без экстраполяции.
Первоначальные точки 100/1000/10000 получены без фонового предохранителя;
остальные — с ним. В таблицах новых точек дополнительно есть VmSwap.

Графики — log–log, медианы и min–max трёх успешных
прогонов. Эмпирическая линейная модель CPU Go вычисляется генератором
таблиц только для 100–20000 правил. Она описывает этот DNS-корпус,
распределение правил и состояние работающего роутера, не доказывая
универсальную зависимость или алгоритмическую сложность.
